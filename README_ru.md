# Complex Number Lab

CLI-калькулятор комплексных чисел на **Guile Scheme**: алгебраическая, тригонометрическая и экспоненциальная формы, арифметика, целые степени, все корни n-й степени, настраиваемая точность, автоматический журнал расчётов и графики на плоскости Аргана через **gnuplot**.

## Возможности

**Арифметика и анализ**
- сложение, вычитание, умножение, деление;
- возведение в целую степень (включая отрицательную и нулевую);
- извлечение **всех** корней n-й степени (формула Муавра);
- для каждого числа: `Re(z)`, `Im(z)`, `|z|`, `arg(z)` в радианах **и градусах**;
- тригонометрическая и экспоненциальная формы в радианах **и градусах**;
- «полный вид» числа — цепочка равенств `алгебраическая = тригонометрическая = экспоненциальная`.

**Интерфейс**
- полностью английский UI;
- математические обозначения вместо словесных подписей: `Re(z)`, `Im(z)`, `|z|`, `arg(z)`;
- мнимая часть печатается в виде `4.0000*i`;
- настраиваемая точность: **0–12 знаков** после запятой (по умолчанию 4);
- эстетическое обрамление вывода (`****`, `<<<< >>>>`, `____`, `----`);
- в блоке операции показываются **оба операнда** и строка `expression` — видно, что на что умножается/делится;
- ошибки не роняют программу: сообщение печатается внутри рамки, цикл продолжается.

**Журнал**
- файл `complex-lab.log` создаётся автоматически при старте, рядом со скриптом;
- режим append — история не теряется между запусками;
- метки `SESSION START` / `SESSION END`, timestamp у каждого блока;
- в лог попадает всё: операнды, выражение, результаты во всех формах, ошибки, пути к картинкам.

**Графики (только `complex_plot.scm`)**
- диаграмма Аргана: векторы из начала координат, точки, подписи, окружность модуля;
- корни n-й степени — все точки на окружности `|z|^(1/n)` и правильный n-угольник;
- автоматическое сохранение PNG у каждой операции + путь в журнале;
- интерактивное окно gnuplot по пунктам `[9]` / `[0]`;
- переключатель авто-PNG `[p]`, чтобы не плодить файлы;
- корректная работа без gnuplot и без дисплея (headless/SSH).

## Требования

- **Guile** 2.2+ (рекомендуется 3.0). Используемые модули `ice-9 format`, `ice-9 rdelim`, `ice-9 popen` входят в стандартную поставку.
- **gnuplot ≥ 5.0** — только для `complex_plot.scm`, опционально:
  - нужны *inline datablocks* (`$D << EOD`), появившиеся в 5.0;
  - для PNG — терминал `pngcairo`;
  - для окна — любой из `qt`, `wxt`, `x11` (пробуются по очереди).

Разрабатывалось под Linux. Под Windows проще всего через WSL.

## Ввод данных

Число вводится по частям:

```
  Enter z1:
    Re(z1) = 3
    Im(z1) = 4
```

- принимаются целые, десятичные (`-2.5`), научная нотация (`1e3`), рациональные (`1/2`);
- пробелы по краям обрезаются, пустой ввод и мусор — повторный запрос;
- комплексные литералы вида `3+4i` **не** парсятся, только два действительных числа;
- степень `n` и порядок корня требуют целого значения;
- лимиты: степень `|n| ≤ 1000`, порядок корня `1 ≤ n ≤ 100`, точность `0 ≤ d ≤ 12`.

Лимиты намеренные: защита от зависания на гигантских степенях и от вывода тысяч строк/точек.

## Математика и формы представления

Внутреннее представление — пара `(re . im)`.

```
z = a + b*i

сложение:      (a + c) + (b + d)*i
умножение:     (a*c - b*d) + (a*d + b*c)*i
деление:       ((a*c + b*d) + (b*c - a*d)*i) / (c^2 + d^2)

модуль:        |z|   = sqrt(a^2 + b^2)
аргумент:      arg z = atan2(b, a)          [-pi, pi]

тригонометр.:  |z| * (cos(arg z) + i*sin(arg z))
экспоненциал.: |z| * e^(i*arg z)

корни (Муавр): z_k = |z|^(1/n) * ( cos((arg z + 2*pi*k)/n)
                                + i*sin((arg z + 2*pi*k)/n) ),  k = 0..n-1
```

Точность влияет **только на отображение**: внутри считается с полной точностью Guile (exact-рациональные и double). Округление при выводе — банковское (`round-half-to-even`), как в стандартном `round`.

Соглашения: `arg(0) = 0`, `z^0 = 1` (включая `0^0`), отрицательная степень нуля даёт ошибку деления на ноль.

  |z2|           = 2.2361

  trig (rad)     = 2.2361 * (cos(2.0344) + i*sin(2.0344))

## Журнал расчётов

Файл **`complex-lab.log`** появляется автоматически при запуске, в каталоге скрипта, и дописывается (append). Каждая операция — это тот же блок, что на экране, плюс метка времени.

```
=========== SESSION START  2026-11-22 14:25:30 ===========
script dir: /home/user/complex-number-lab
gnuplot: yes | auto PNG: on

[2026-11-22 14:26:04]
************************************************************************
                   <<<<  DIVISION:  w = z1 / z2  >>>>
...
  plot           = /home/user/complex-number-lab/plot-20261122-142530-12345-3.png
...
=========== SESSION END    2026-11-22 14:31:12 ===========
```

Особенности:
- ошибки тоже логируются — журнал отражает реальный ход работы;
- если каталог недоступен для записи, программа не падает: предупреждает и работает без лога;
- ротации/автоочистки нет — файл растёт, чистите вручную.

Что не стоит коммитить (добавьте в `.gitignore`):

```gitignore
complex-lab.log
plot-*.png
```

## Графики (complex_plot.scm)

Что рисуется:

| Операция | Содержимое графика |
|---|---|
| `+`, `-`, `*`, `/` | векторы `z1`, `z2`, `w` из начала координат, точки с подписями, окружность максимального модуля |
| `z^n` | векторы `z` и `w` — видно поворот и растяжение |
| Inspect / Plot z | вектор `z`, окружность `|z|` |
| Корни / Plot roots | все `z_k` на окружности `|z|^(1/n)` + правильный n-угольник |

Режимы:
- **авто-PNG** — включён по умолчанию: каждая операция сохраняет `plot-<session>-<n>.png` рядом со скриптом, путь пишется и на экран, и в лог. `session` = дата-время + PID, поэтому перезапуски не затирают старые картинки;
- **окно** — пункты `[9]` (число) и `[0]` (корни): сохраняется PNG **и** открывается интерактивное окно (`gnuplot -persist`, терминалы `qt` → `wxt` → `x11`);
- **`[p]`** — тумблер авто-PNG. Явные `[9]`/`[0]` сохраняют картинку всегда.

Важные детали реализации:
- `set size ratio -1` — равный масштаб осей, иначе окружность превратится в эллипс и геометрия соврёт;
- PNG через `pngcairo` (800×800) работает **без дисплея** — по SSH картинка сохранится, а строка `window` покажет `failed (no display?)`;
- наличие gnuplot проверяется один раз при старте, stderr подавлен, код возврата анализируется;
- возможные значения строки `plot`: путь к файлу, `skipped (gnuplot not found)`, `skipped (non-finite value)`, `off (auto PNG disabled)`, `failed (gnuplot error)`.

## Ограничения и особенности

- степени только **целые**; дробные и комплексные показатели не поддерживаются;
- лимиты: `|n| ≤ 1000` (степень), `1 ≤ n ≤ 100` (корень), `0 ≤ точность ≤ 12`;
- ввод по частям `Re` / `Im`; строка `3+4i` или полярная форма не парсятся;
- точность — только форматирование вывода, не влияет на вычисления;
- очень большие результаты могут стать `+inf.0`: отображаются как есть, график помечается `skipped (non-finite value)`;
- gnuplot < 5.0 не поддерживается (нужны inline datablocks); при отсутствии `pngcairo` PNG вернёт `failed`;
- лог и PNG не ротируются и не удаляются автоматически;
- при длинных числах (точность 10–12) строки могут выходить за ширину рамки в 72 символа — косметика, на расчёты не влияет.

## Идеи для развития

- ввод одной строкой `3+4i` и полярная форма `r∠φ`;
- дробные степени, комплексные `exp`, `log`, `sin`, `cos`;
- параллелограмм сложения и анимация умножения как «поворот + растяжение»;
- экспорт SVG прямо из Scheme (вариант без gnuplot);
- ротация журнала, экспорт расчётов в CSV/JSON;
- юнит-тесты на SRFI-64.
